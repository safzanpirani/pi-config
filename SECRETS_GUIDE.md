# Secrets Guide

This file documents which secrets belong where for the current Pi setup.

## Rule of thumb

- **Public repo (`pi-config`)**: placeholders only, never real secrets.
- **Private repo (`pi-config-private`)**: real secrets and private bootstrap state are allowed.
- **Best practice**: keep secrets in JSON/env config files, not TypeScript source.

## Current secret-bearing areas

| Area | File | Public repo | Private repo |
|---|---|---|---|
| Provider auth | `auth.json` | `auth.example.json` placeholders only | Real OAuth/API-key values |
| Shell env secrets | `.env.pi`, `.env.pi.json` | Excluded | Real env values for fast bootstrap |
| MCP server env | `mcp.json` | Placeholder env values | Real env values allowed |
| Model provider config | `models.json` | Env-var names/placeholders only | Real inline values allowed |
| Runtime account state | `antigravity-accounts.json`, `codexswap.json`, `codex-fast.json` | Excluded | Tracked for exact machine bootstrap |
| Extension config | `extensions/exa-remote.json` | Excluded | Real Exa API key allowed |
| Runtime/cache data | `sessions/`, `cache/`, `subagents/`, `pi-fff/`, `git/`, `npm/`, `node_modules/` | Excluded | Excluded; regenerated by Pi |

## Public repo checks before pushing

Before pushing `pi-config`, verify:

```bash
jq empty settings.json models.json mcp.json auth.example.json
git status --short
```

Then run a secret scan that checks for:

- exact secret values from the private/live config
- common token formats (`sk-*`, `sk_*`, GitHub tokens, JWTs, private keys)
- accidental secret files (`auth.json`, `.env.pi*`, `codexswap.json`, `extensions/exa-remote.json`)

If any exact secret value appears in `pi-config`, stop and remove it before committing.
